Jobber — Парсер вакансий из Telegram

Jobber — это автоматический сборщик вакансий, стажировок и проектов для начинающих IT-специалистов.
Он читает посты из указанных Telegram-каналов, фильтрует их по десяткам критериев, определяет направление (разработка, дизайн, аналитика, тестирование, менеджмент), тип (вакансия, стажировка, проект), формат (удалёнка / офис), оплату и дедлайн. Результаты сохраняются в Google Sheets и локальную SQLite базу, чтобы не дублировать уже обработанные посты.

Управление парсером происходит через Telegram-бота – можно добавить или удалить канал, запустить поиск, посмотреть список.
📦 Что входит в проект

    Парсер на базе Telethon — читает сообщения из каналов.

    Классификатор на правилах (ключевые слова, регулярные выражения, стоп‑слова) — определяет релевантность, направление, тип.

    Дедупликация по содержимому поста (MD5 хеш нормализованного текста).

    Хранение в SQLite — уже обработанные посты не попадают в таблицу повторно.

    Экспорт в Google Sheets (листы Alpha и Сводка) с форматированием.

    Telegram-бот на aiogram — команды для управления каналами и запуска парсинга.

🚀 Как начать пользоваться (пошаговая инструкция)
1. Склонируйте репозиторий
bash

git clone https://github.com/your-username/jobber.git
cd jobber

2. Установите зависимости

Рекомендуется использовать виртуальное окружение:
bash

python -m venv venv
source venv/bin/activate      # Linux/Mac
venv\Scripts\activate         # Windows

Установите пакеты:
bash

pip install -r requirements.txt

Если файла requirements.txt нет, установите вручную:
bash

pip install telethon aiogram gspread google-auth python-dotenv

3. Получите Telegram API ключи

    Перейдите на my.telegram.org/apps

    Авторизуйтесь

    Создайте приложение (если ещё нет)

    Скопируйте api_id и api_hash

4. Создайте сервисный аккаунт Google Sheets

    Перейдите в Google Cloud Console

    Создайте проект (или выберите существующий)

    Включите Google Sheets API и Google Drive API

    Создайте сервисный аккаунт (IAM & Admin → Service Accounts)

    Сгенерируйте JSON‑ключ и сохраните файл

    Скопируйте email сервисного аккаунта (например, jobber@...gserviceaccount.com)

    Создайте Google Sheets документ (или используйте существующий)

    Поделитесь этим документом с email сервисного аккаунта (права редактор)

    В URL таблицы найдите spreadsheetId (часть между /d/ и /edit)

5. Настройте переменные окружения

Создайте в корне проекта файл .env:
ini

# Telegram API
TELEGRAM_API_ID=1234567
TELEGRAM_API_HASH=ваш_api_hash
TELEGRAM_PHONE=+79001234567    # номер телефона аккаунта Telegram

# Google Sheets
GOOGLE_SPREADSHEET_ID=ваш_spreadsheet_id
GOOGLE_SERVICE_ACCOUNT_FILE=credentials/google_service_account.json

    Файл с JSON‑ключом положите в папку credentials/ (создайте её)

    Укажите путь в .env (можно абсолютный или относительный)

6. Подготовьте базу данных (создастся автоматически)

При первом запуске SQLite файл data/aggregator.db и таблицы создадутся сами.
Если хотите, можете разместить базу в другом месте — укажите DATABASE_PATH в .env.
7. Запустите Telegram-бота
bash

python -m app.bot

(уточните точную команду запуска вашего бота — обычно это main.py или bot.py)

Бот будет отвечать на команды:

    /start — приветствие

    /help — список команд

    /jjjoobbb — запустить парсинг (сбор вакансий)

    /chennels — показать список каналов для парсинга

    /add_chennel — добавить канал (можно несколько)

    /remove_chennel — удалить канал

8. Добавьте первые каналы

Напишите боту:
text

/add_chennel hubdgtl cozy_hr edujobs workenot

Каналы указываются без @, через пробел, запятую или новую строку.
9. Запустите парсинг
text

/jjjoobbb

Бот сообщит о начале и по окончании скинет ссылку на Google Sheets с результатами.
⚙️ Как это работает (кратко)

    Бот проходит по всем добавленным каналам, читает последние MESSAGES_LIMIT сообщений (по умолчанию 30).

    Игнорирует сообщения короче MIN_MESSAGE_LENGTH (100 символов) и старше MAX_POST_AGE_DAYS (14 дней).

    Пропускает уже обработанные посты (сверяет URL и хеш текста).

    Классификатор проверяет:

        есть ли обязательные слова (стажировка, junior, без опыта и т.д.);

        нет ли стоп‑слов (магистратура, руководитель, senior, онлайн-курс и др.);

        не зарубежная ли вакансия;

        не требует ли офис в чужом городе (кроме крупных компаний);

        не слишком ли большой опыт (3+ лет);

        не руководящая ли должность;

        не требуется ли высшее образование.

    Если пост релевантен — определяется направление, тип, оплата, формат, компания, дедлайн, вычисляется score.

    Посты с score >= 5 экспортируются в Google Sheets (лист Alpha), а сводка по направлениям сохраняется на лист Сводка.

    Все успешно экспортированные посты записываются в SQLite, чтобы при следующем запуске не дублироваться.

🛠 Настройка под себя

Все параметры находятся в app/service/parser/channel/config.py:

    REQUIRED_KEYWORDS — слова, без которых пост не релевантен.

    STOP_KEYWORDS — слова, при наличии которых пост сразу отклоняется.

    BIG_COMPANIES — список крупных компаний, которым разрешён офис в любом городе.

    TARGET_CITY — целевой город для офисных вакансий (по умолчанию чебоксар).

    MESSAGES_LIMIT, MAX_POST_AGE_DAYS, MIN_MESSAGE_LENGTH — лимиты парсинга.

    DIRECTIONS — словари ключевых слов для каждого направления.

    OPPORTUNITY_TYPES — ключевые слова для определения типа.

После изменения config.py перезапустите бота.

❓ Частые вопросы

Что делать, если бот не запускается?
Проверьте, что в .env указаны правильные API_ID, API_HASH, PHONE. Убедитесь, что файл с JSON‑ключом сервисного аккаунта существует и доступен.

Как обновить список каналов?
Команды бота: /add_chennel и /remove_chennel. После изменения каналы сохраняются в базе.

Почему парсинг долго выполняется?
Каналы читаются последовательно с паузой 2 секунды между ними, чтобы не попасть под ограничения Telegram. Время зависит от количества каналов и сообщений.

Можно ли парсить без бота, просто из командной строки?
Да, в проекте есть скрипт app/service/parser/channel/testing.py. Запустите:
bash

python -m app.service.parser.channel.testing --channels hubdgtl cozy_hr --limit 20

Как очистить базу и начать с нуля?
Удалите файл data/aggregator.db — при следующем запуске он создастся заново.
